You can now build, break and fix things that many graduates have never touched. This module is about the other half of the job: making other people understand what you did. You learn the English that documentation and reports use, a simple order for explaining a project, how to write a README and a CV that show evidence instead of claims, how interviews work, and which certifications are worth your money now. As in the rest of the course, you check your own writing with the terminal.

## What you will learn

- How to read usage lines and error messages word by word, and write a bug report with steps, expected result and actual result.
- How to explain a project in two minutes: problem, approach, result, with real numbers.
- What a README needs on its first screen, and how to prove every line of it in a fresh clone.
- How to write a one-page CV with evidence, and set up LinkedIn and GitHub to back it up.
- How interviews work, how to answer with STAR and how to solve a coding question out loud.
- Which certifications help a beginner, which can wait, and how to decide with job advertisements.

## Before you start

You need the terminal, `grep`, pipes and small shell loops from [Module 1](../linux/), git and GitHub from [Module 2](../git/), and Python from [Module 3](../python/). Most examples come from your own `mylab`, so it helps to have done the project steps of the earlier modules, up to [Module 15](../ai/). If you skipped some, every lesson recreates what it needs.

## Project step

The `mylab` README still describes the project as it was in Module 2. You rewrite it with the template from lesson 16.3: a one-sentence description, a real example from the log analyzer, a quick start, the contents and the limits. Then you prove it: every file it names exists, its example matches the real output, and its quick start works in a fresh clone. Finally you push it, give the repository a description and topics, and pin it on your GitHub profile.
